# Chrona M3 — Live App: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A running cross-platform desktop app — `chrona-app` — that listens to a microphone live (or a simulated watch, or a replayed WAV), shows the classic paper-tape trace plus rate/beat-error/amplitude numerals with tier badges at ~10 Hz, and records sessions to disk; preceded by the two mandatory M2-debt tickets (octave-guard stress matrix; `current()` performance).

**Architecture:** Three new crates on top of the frozen `chrona-dsp` core: `chrona-audio` (cpal capture → lock-free ring, per-OS quirks isolated), `chrona-session` (WAV + JSON-sidecar recording, replay, TOML config store), `chrona-app` (eframe/egui; audio callback → `rtrb` ring → DSP thread owning the `Analyzer` → `triple_buffer` snapshots → UI). The GUI stays a thin shell over pure, unit-tested presenter functions (tape geometry, formatting, device fallback); real-mic behavior is covered by a written manual test protocol since CI has no microphone.

**Tech Stack:** existing (rustfft/realfft, biquad, hound, clap, serde) + new workspace deps: `cpal 0.18` (with `pipewire` feature on Linux), `rtrb 0.4`, `triple_buffer 9`, `eframe 0.36`, `rfd 0.15` (native file dialogs), `directories 6`, `toml 0.9`.

**Spec:** `docs/superpowers/specs/2026-08-20-chrona-timegrapher-design.md` (§4 architecture/threading, §6 GUI, §7 capture, §8 sessions/persistence, §9 error handling, §12.3 M3 scope). Also binding: `docs/superpowers/notes/m2-followups.md` — Tasks 1–2 discharge its mandatory first-week debt. The spec is the authority.

## Global Constraints

- Everything from M1/M2 Global Constraints still holds: MIT OR Apache-2.0, no GPL code, no `unwrap()`/`expect()` in library code reachable from user input (tests exempt; documented-invariant `.expect` allowed), deterministic seeded tests, `cargo fmt --all --check` + `cargo clippy --all-targets --workspace -- -D warnings` green at every commit, `cargo fmt --all` before staging
- Dependency direction (spec §4): GUI → session/audio → dsp, never reverse; `chrona-dsp` gains NO new dependencies; nothing below `chrona-app` knows egui
- Threading discipline (spec §4): no allocation, no locks, no I/O in the cpal callback — it may only mono-ize into pre-allocated state and push to the `rtrb` producer + bump atomics; the DSP thread owns the `Analyzer`; UI reads `triple_buffer` snapshots
- **Octave probe constants (1.8× floor, ±NBINS/16 window, 0.5 cluster factor) are FROZEN until Task 1's stress matrix is committed and green** (M2 final-review ruling)
- Performance bar (m2-followups #2): `Analyzer::current_metrics()` (the renamed incremental form) p50 **< 10 ms in release** with a full 32 s ring at 48 kHz, measured by the Task 2 harness; incremental results must equal the one-shot baseline on identical input (equivalence test)
- Breaking-window items land ONLY in Task 2 (one API break, everything downstream updated in the same task): `rate_source: Option<RateSource>`, `extract_events` loses its vestigial `env_start_abs` parameter, `Analyzer::clipped_samples()` accessor, `&mut self` on the metrics call
- UI honesty (spec §3.1/§6): metrics below tier render as "—" with the reason, never fabricated; rate shows the `[uncalibrated timebase]` badge when ppm == 0; a source badge only when a rate exists
- Error handling per spec §9: device disconnect → reconnect loop + banner; stream-opens-but-silent ≥ 3 s → Windows-privacy hint banner; clipping → red meter + warning; mic permission denied → blocking explainer; DSP-thread panic must not take down the UI (caught at thread boundary, fault banner + session close)
- Session format (spec §8): 32-bit float WAV + versioned JSON sidecar (`schema_version: 1`, device name, negotiated sample rate, ppm at record time, lift angle, bph mode, position optional, start time UTC-unix-seconds, app version); replay = re-run the pipeline from the WAV
- Third-party API drift rule (M1-T4 precedent): for cpal/eframe/rfd/triple_buffer/rtrb call shapes, the plan's code is a strong reference — if a signature differs from the shipped crate, adapt the internals against docs.rs and say so in the report; the public contracts and the tests are the requirement
- GUI tasks: subagents verify via `cargo build -p chrona-app` + unit tests of presenter functions; do NOT launch windows in CI or leave app processes running. Real-screen verification is the Task 12 manual protocol, run by the human

## Decisions locked by this plan

- **Stress matrix runs as `#[ignore]`d tests** executed by a dedicated CI step (`cargo test -p chrona-dsp --release -- --ignored`, ubuntu-only job) so the default suite stays fast while the matrix stays binding in CI.
- **Incremental analysis design (Task 2):** the analyzer caches fold + templates + extracted events; on each `current_metrics()` call it (a) refolds only when ≥ 1 s of new audio arrived or the period estimate drifted > 0.1 % (then re-extracts everything — rare), else (b) extracts only beats in the newly-arrived region and appends to the cache, evicting events older than the ring. Metrics/tier computation over the averaging window is unchanged. Equivalence is testable because extraction is deterministic given (raw, env, profile).
- **The paper tape draws from real per-beat events**, exposed via `Analyzer::tape_events()` (cheap copy of the cache). Deviation math (presenter): `dev_k = (t_k − t_0) − k·T_beat_nom`, wrapped to `(−T_wrap/2, T_wrap/2]` with a user-selectable display range; x = beat index; tic/toc colored; slope = rate, band separation = beat error (spec §6).
- **Simulate mode is a first-class source** (`chrona-app --simulate [--rate .. --beat-error .. --amplitude .. --snr ..]`): a thread synthesizes the watch in 100 ms chunks and feeds the same ring as the mic. It exists for demos, GUI development, and end-to-end app testing without hardware — and it is how subagents can sanity-run the pipeline headlessly (`--simulate --headless-seconds N` prints final metrics and exits without opening a window).
- **Replay (M3 scope)** = open WAV → run at max speed on the DSP thread → tape + numerals show the whole-file result (a "REPLAY" banner replaces live health banners). Scrubbing/timeline is M4+.
- **Time formatting without new deps:** session filenames `chrona-YYYYMMDD-HHMMSS.wav` via a small pure `civil_from_unix()` (Howard Hinnant's days-from-civil inverse, ~20 lines, unit-tested).
- **Position tagging** is a free-text optional field in the record panel (DU/DD/CU/CD/CL/CR quick buttons); the six-position summary table is M4.
- **chrona-audio's cpal callback mono-izes by channel-average** (matches `wav.rs` semantics) with a pre-allocated scratch; overruns (ring full) drop newest samples and bump an atomic counter surfaced in the UI.
- Config store: `directories::ProjectDirs::from("", "", "chrona")`; `config.toml` holds `default_lift`, `last_device`, and `[device_ppm]` name→ppm map (device *names* as keys — cpal 0.18 stable IDs are used at open time, names for persistence readability).

  - `MetricsSnapshot.rate_source: Option<RateSource>` — `Some` iff `rate_s_per_day` is `Some`

  - Performance bar: `current_metrics()` p50 < 10 ms release on a full 32 s ring (harness below)

**Incremental algorithm (concrete):** `Analyzer` gains
```rust
struct AnalysisCache {
    profile: crate::fold::FoldProfile,
    halved: bool,
    t_osc_used: f64,            // nominal t_osc the profile was folded at (seconds)
    env_len_at_fold: usize,     // env ring len when folded (fold_start recomputation anchor)
    env_start_at_fold: u64,     // absolute env index of env_window[0] at fold time
    extracted_through_cycle: usize,
    events: Vec<BeatEvent>,     // absolute-seconds events, ascending, pruned to ring span
    last_fold_total: u64,       // raw total_pushed at last fold
}
cache: Option<AnalysisCache>,
```
`current_metrics()`: (1) get `raw_est = period.estimate()?`; (2) refold when cache is None, or `raw_ring.total_pushed() − last_fold_total ≥ sr` (≥1 s new), or `|t_osc − t_osc_used|/t_osc_used > 0.001` — refolding recomputes profile+halved via the guard, clears events, resets `extracted_through_cycle = 0`; (3) rebuild the env/raw windows exactly as M2 did (including the trailing-partial trim), compute `cycles`, and call `extract_events_from(.., extracted_through_cycle)` appending only new events (their `beat_index` continues the grid: `2·(cycle)+slot` relative to the CURRENT fold window — on append-without-refold the fold window start is unchanged by construction of step 2's guard, because fold_start depends only on `env.len() mod t_osc` which shifts as the ring slides… it does NOT stay fixed as the ring slides). **Resolution (design decision):** between refolds, freeze the extraction geometry: keep using the fold-time `env_start_at_fold`/`env_len_at_fold` to place cycle boundaries, extending cycles forward in absolute time (`cycle c` starts at `fold_time_origin + c·t_osc_env` env samples, absolute); extract new cycles as the ring grows past them. Events are timestamped absolutely, so appending is stable; the ≥1 s refold cadence bounds drift (< 0.1 % period drift × 1 s ≪ gate width). Prune events older than `newest − 32 s`.
(4) metrics/tier over the averaging window exactly as M2 (unchanged code path, now reading `cache.events`).

    let host = cpal::default_host();
    let device = match device_id {
        Some(id) => find_by_id(&host, id)?, // devices() scan comparing our stable id string
        None => host.default_input_device().ok_or(CaptureError::NoDevice)?,

    let (rate, channels) = negotiate(&device)?; // supported_input_configs → choose_config

        &config_for(rate, channels),

                crate::monoize::average_into(data, channels as usize, &mut scratch);
                let mut written = 0;
                // push as much as fits; count the rest as overrun
                if let Ok(mut chunk) = producer.write_chunk(scratch.len().min(producer.slots())) {
                    // copy scratch prefix into the chunk (two slices), commit
                    …
                }
                let dropped = scratch.len() - written;
                if dropped > 0 { health.add_overrun(dropped as u64); }
